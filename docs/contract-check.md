# Проверка контракта практики 2

Проверили контракт FairfaxStat по колоде К1–К10: [архитектуру](architecture.md), [автомат Job](job-lifecycle.md), [OpenAPI](api/openapi.yaml), [правила HTTP](api/README.md), [контракт Tool](tool-contract.md) и ADR-0001–0004.

Для всех десяти карт определены ответы. Отмену Job из К6 не поддерживаем; причина и условия пересмотра записаны в ADR-0004.

## К1–К10

| Карта | Ответ контракта |
|---|---|
| **К1 Двойной клик** | При одном секрете, ключе и нормализованных параметрах создаётся ровно один Job: первый ответ `202`, второй `200` с прежним ID и текущим состоянием. Конкуренцию разрешают уникальность пары и транзакция; возможный `503` требует повтора с тем же ключом. [HTTP: повтор отправки](api/README.md#idempotency), OpenAPI `POST /jobs`, `IdempotencyKey`; [ADR-0003](adr/0003-request-identity.md). |
| **К2 Ответ потерялся** | Клиент заранее сохраняет секрет, ключ и запрос, затем повторяет тот же POST. Если commit состоялся — `200` и прежний Job; иначе — `202` с новым сохранённым Job. Когда ID уже известен, можно читать GET. Ключи переживают рестарт и не истекают в v1. [HTTP: повтор отправки](api/README.md#idempotency), OpenAPI `createJob`, `getJob`. |
| **К3 Неизвестная операция** | `400 UNKNOWN_TOOL`, единый ErrorEnvelope, `details` указывает `body /operation`; Job и внешний запрос отсутствуют. Строковое имя внутреннего Tool тоже нельзя вызвать напрямую. [HTTP: ввод](api/README.md#validation), OpenAPI `CreateJobRequest`, `BadRequest.examples.unknownTool`; [границы Tool](tool-contract.md). |
| **К4 Кривые параметры** | Отсутствие поля, тип, лишнее свойство или недопустимый ID дают `400 VALIDATION_ERROR`; неразбираемый JSON — `400 INVALID_JSON`. `details` содержит точное поле, например `/params/match_id`, и машинную причину; Job не создан. [HTTP: ошибки](api/README.md#errors), OpenAPI `ErrorEnvelope`, `InvalidMatchId`, `CreateJobRequest`. |
| **К5 Воскрешение** | Терминальный Job неизменен. Повтор прежнего ключа даёт `200` с прежним результатом/ошибкой. Новый ключ создаёт другой Job (`202`); PATCH ресурса даёт `405`, несуществующий `/restart` — `404`. [Запрещённые переходы](job-lifecycle.md#forbidden), [ADR-0004](adr/0004-no-cancellation.md), OpenAPI `createJob`, `x-router-errors`. |
| **К6 Отмена** | Сознательно не поддерживается: закрытие страницы не отменяет Job, промежуточный отчёт не публикуется. `/cancel` даёт `404 ROUTE_NOT_FOUND`; изменение/удаление ресурса — `405 METHOD_NOT_ALLOWED`. Причина — ограниченная обработка чтения и дополнительный протокол гонки отмены с commit. [ADR-0004](adr/0004-no-cancellation.md), [маршрутизация](api/README.md#routing), OpenAPI `x-router-errors`. |
| **К7 Огромный вход** | Тело >8 192 байт получает `413 PAYLOAD_TOO_LARGE` до JSON-разбора; длинное/невалидное поле в малом теле — `400` с полем. Metadata >32 MiB после распаковки завершают Job `SOURCE_RESPONSE_TOO_LARGE`. Большие дополнительные секции исключаются с предупреждением, итог ограничен 16 MiB. [Ввод](api/README.md#validation), [пределы Tool](tool-contract.md#bounds), OpenAPI `x-limits`, `PayloadTooLarge`. |
| **К8 Чужой или несуществующий id** | Невалидный UUID — `400`. Корректный чужой и отсутствующий ID при корректном секрете — одинаковый `404 JOB_NOT_FOUND`, без данных владельца. Без секрета — `401`; результат проверяет то же владение. [Владелец Job](api/README.md#identity), [ADR-0003](adr/0003-request-identity.md), OpenAPI `getJob`, `getJobResult`, `JobNotFound`. |
| **К9 Перезапуск сервера** | Постоянная БД сохраняет состояние/попытки. После истечения lease 90 с Recovery переводит `running` в `retry_wait` с повтором через 5 с либо в `failed WORKER_LOST` при трёх попытках. Старый token отвергается. Отчёт и успех фиксируются вместе; один опубликованный результат. [Восстановление](job-lifecycle.md#recovery), [ADR-0002](adr/0002-durable-jobs.md), OpenAPI `Job`, `Error`. |
| **К10 Внешний сервис** | Молчание 30 с — `SOURCE_UNAVAILABLE`, ограниченный повтор; мусор/переименованное обязательное поле — `SOURCE_DATA_INVALID`, `failed` без повтора. Повреждённый дополнительный блок даёт предупреждение и успешный остальной отчёт. 429/503 учитывают `Retry-After`, 504 не повторяется. Клиент читает `200 Job` с `last_error`/`error`, а не сырой ответ источника. [Ошибки источника](tool-contract.md#source-errors), [повторы](job-lifecycle.md#retry), OpenAPI `getJob`, `Error`, `MatchReport`. |

Имена `CreateJobRequest`, `ErrorEnvelope` и другие ссылки на схемы относятся к узлам в `openapi.yaml`.

## Что предложил ИИ

Для дополнительной проверки передали модели контракт и колоду. Задача — найти три ситуации, для которых нужно уточнить правила обработки.

Промпт проверки:

> Ты атакующий в контрактном покере. Используй приложенные architecture.md, job-lifecycle.md, api/openapi.yaml, api/README.md, tool-contract.md и ADR-0001–0004 как проект контракта сервиса анализа матча Deadlock. Контекст p1: Job асинхронный, пять состояний, до трёх попыток, нет аккаунтов/Steam login/отмены, нельзя выдавать отсутствующие данные за нули. Колода: К1 — двойной клик; К2 — ответ потерян; К3 — неизвестная операция; К4 — кривые параметры; К5 — повтор завершённого Job; К6 — отмена; К7 — вход в тысячу раз больше обычного; К8 — чужой или отсутствующий id; К9 — рестарт во время running; К10 — внешний сервис молчит 30 секунд, возвращает мусор или переименовал поле. Найди ещё три конкретные ситуации, для которых проекту нужны более точные правила, не повторяя эти общие карты. Для каждой дай последовательность действий, наблюдаемую проблему и точное место/правило, которое надо добавить. Отделяй пробелы контракта от ошибок ещё не написанного кода. Не утверждай, что что-либо реализовано или протестировано. После правок проверь, что предлагаемое решение не противоречит p1.

| Находка ИИ | Решение | Что закреплено и почему |
|---|---|---|
| **ID без потери точности.** Два разных валидных uint64, например `9007199254740992` и `9007199254740993`, могут слиться при преобразовании через JavaScript Number. Общей проверки «положительное целое» недостаточно: запрос уйдёт за другим матчем, сравнение ключей даст ложный повтор. | Принято | Внешний HTTP-вход принимает только строку, нормализует её без float и проверяет верхнюю границу uint64. Исходный числовой ID парсится с точностью целого. [HTTP: ввод](api/README.md#validation), OpenAPI `CreateJobRequest.params.match_id`, `MatchId`; [первый Tool](tool-contract.md#fetch). |
| **Сумма допустимых секций слишком велика.** Каждая секция отдельно укладывается в лимит, но вместе они превышают 16 MiB. Простой отказ всего Job противоречил бы правилу сохранения корректной обязательной части отчёта. | Принято | Есть порядок исключения целых дополнительных секций и `OPTIONAL_DATA_TOO_LARGE`, без тихого обрезания. Только слишком большая обязательная сводка даёт `RESULT_TOO_LARGE`. [Объём результата](tool-contract.md#bounds), OpenAPI `Section`, `Warning`, `MatchReport`. |
| **Релиз между постановкой и выполнением.** Job стоит в очереди либо ждёт повтор, Registry заменён новой версией парсера. Без фиксации версии одинаковый Job может сменить смысл обработки или смешать форматы. | Принято | Версии Tool фиксируются при создании. Registry удерживает их до завершения Job; отсутствующая версия даёт `TOOL_VERSION_UNAVAILABLE`, без молчаливой подмены. Каждая попытка использует один снимок. [Версии Tool](tool-contract.md#versions), [переходы Job](job-lifecycle.md), OpenAPI `Error.code`. |

Все три предложения приняли. Изменения отражены в HTTP-контракте, ограничениях отчёта и правилах версионирования Tool.

## Сверка с практикой 1

| Требование p1 | Где уточнено в p2 |
|---|---|
| С1: асинхронное создание и ключ отправки | `POST /jobs`, 202/200/409, нормализация и транзакция ключа. |
| С2: статус переживает обновление страницы | `GET /jobs/{id}`, постоянный JobStore, секрет браузера и восстановление. |
| С3: отчёт, события, статистика и карта с ограничениями источника | MatchReport, шесть отдельных секций, `null` и предупреждения, проверка семантики координат. |
| С4: неверный ID и отсутствие metadata — разные случаи | HTTP 400 до Job; `MATCH_DATA_UNAVAILABLE`/`SOURCE_DATA_INVALID` внутри Job. |
| С5: три попытки, 30 с, задержки 5/30 с, Retry-After ≤120 с | Автомат, единая политика Dispatcher, таблица ошибок Tool. |
| Пять состояний, терминалы неизменны, отмены нет | Полная матрица переходов и ADR-0004. |

Анонимный секрет ограничивает доступ к Job без регистрации аккаунтов. Пять состояний, бюджет повторов и ограничения источника сохранены из p1.
