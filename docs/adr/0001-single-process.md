# ADR-0001: один процесс и локальные Tool
## Контекст и ограничения

Три участника разрабатывают учебный сервис анализа одного матча. Нужны HTTP-вход, фоновые Job и два последовательных Tool. Независимые релизы Tool, GPU и распределённое масштабирование в первой версии не требуются. HTTP-запрос создания должен быстро вернуть сохранённый Job, не ждать внешнего API.

## Решение

Размещаем HTTP-вход, Dispatcher, Registry, Scheduler и оба Tool в одном серверном процессе. Обработку выполняет отдельный worker внутри процесса; HTTP-обработчики не выполняют анализ. Одновременно работает один Job. Tool вызываются локально через общий контракт и не имеют собственного HTTP API. Их входы и выходы проверяются на границах вызова.

Постоянная очередь и данные находятся в SQLite по [ADR-0002](0002-durable-jobs.md). Разделение модулей сохраняем: Tool не видят HTTP и SQLite, Dispatcher не разбирает исходные игровые поля.

## Рассмотренные альтернативы

| Вариант | Почему не выбрали |
|---|---|
| Отдельный сервис на каждый Tool | Потребуются сетевые контракты, развёртывание и обработка частичных отказов между нашими сервисами без текущей потребности. |
| HTTP-процесс и отдельный worker-процесс | Лучше изоляция тяжёлой обработки, но нужны два жизненных цикла и настройка запуска. Для ограниченного размера одного матча начинаем с одного процесса. |
| Полностью синхронный анализ в `POST /jobs` | Потеря соединения скрывает результат, запрос занимает до нескольких десятков секунд и не соответствует сценариям p1. |

## Цена решения

Релиз и отказ процесса общие для HTTP и обработки. Worker делит CPU и память с API. Нужны ограничения размеров и времени, отдельный контур Scheduler/Recovery, а длительный разбор не должен блокировать приём HTTP. Нельзя масштабировать Tool независимо.

## Условия пересмотра

Пересмотреть, если подготовка отчёта регулярно превышает 20 секунд, требуется больше одного активного Job, CPU обработки заметно задерживает HTTP, нужен GPU или отдельный релиз Tool. Первым можно вынести worker, сохранив контракт Tool и HTTP.
