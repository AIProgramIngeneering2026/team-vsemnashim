# FairfaxStat

Сервис анализа конкретного матча Deadlock. Пользователь вводит ID матча, сервис создаёт задачу обработки (Job), получает доступные данные из Deadlock API и формирует отчёт.

Команда: `vsemnashim`. Репозиторий: `team-vsemnashim`.

## Проблема и пользователи

Итоговой таблицы матча внутри игры недостаточно, чтобы понять, как он развивался: когда игрок покупал предметы, где погибал, как менялись его ресурсы и где он находился на карте. Эти сведения могут быть доступны в metadata матча, но представлены большим техническим JSON с числовыми идентификаторами и разными временными рядами.

Сервис предназначен для игроков Deadlock, которые хотят разобрать конкретную сыгранную игру. Он собирает доступные сведения в одном отчёте и явно показывает, каких данных не хватает.

## Основной сценарий

1. Пользователь вводит ID завершённого матча.
2. Сервис проверяет ввод и создаёт Job, возвращая его идентификатор.
3. Пользователь видит состояние обработки и может обновить страницу, не запуская сбор заново.
4. Фоновый обработчик получает metadata, проверяет ответ и подготавливает отчёт.
5. Пользователь открывает отчёт или получает понятное сообщение о причине неудачи.

## Что входит в первую версию

- Веб-интерфейс ввода match ID, состояния Job и просмотра результата.
- Backend с созданием Job, чтением его состояния и выдачей готового отчёта.
- Фоновый обработчик с ограниченными повторными попытками при временных сбоях.
- Постоянное хранение Job, исходного JSON и подготовленного результата.
- Сведения о матче и участниках, итоговая статистика.
- Покупки и продажи предметов, события смертей и целей карты.
- Доступные временные срезы экономики и статистики урона.
- Карта перемещений выбранного игрока по доступным X/Y-отсчётам с выбором времени.
- Явные пометки об отсутствующих или непригодных для отображения дополнительных данных.

## Что не входит

- Прямое подключение к Valve, Steam login, Game Coordinator и собственные Steam-боты.
- Полный сбор всех матчей Deadlock, импорт всей истории игрока и постоянный мониторинг новых игр.
- Загрузка и разбор бинарных replay/demo, покадровое воспроизведение, журнал каждого выстрела.
- Подключение API Statlocker, его рейтинги PP/MVP и воспроизведение закрытых формул.
- Прогноз победы, рекомендации по игре и оценка «правильности» действий игрока.
- Учётные записи пользователей, социальные функции, платежи.
- Отмена Job, ручное редактирование отчётов и автоматическое обновление уже готового результата.

## Источник и ограничения данных

Используем [Deadlock API](https://api.deadlock-api.com/docs) — сторонний community-сервис, а не официальный публичный REST API Valve. Основной запрос: `GET /v1/matches/{match_id}/metadata?disable_steam=true`. Читаем доступные сохранённые metadata; собственную загрузку данных через Steam не инициируем. Для подписей героев и предметов используются справочники `/v1/assets/heroes` и `/v1/assets/items`, сохранённые в локальном кеше.

Источник не гарантирует наличие любого матча и всех дополнительных полей. Отсутствие metadata означает «данные недоступны в источнике», а не «матч не существовал». Недоступность справочника не блокирует отчёт: вместо имени показывается исходный ID.

`damage_matrix` содержит агрегаты разных типов, а не журнал попаданий. Непроверенную интерпретацию матрицы в отчёт не включаем. Для первой версии достаточно явно подписанных показателей урона из `players[].stats`; значения разных типов не суммируются автоматически.

Траектории — дискретные X/Y-отсчёты из metadata. Частота берётся из `interval_s`; наличие секундных данных в одном матче не означает такую же частоту и покрытие у всех матчей.
